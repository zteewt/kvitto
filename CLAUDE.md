# Правила работы с репозиторием — для ИИ-агентов и для человека.

## Что это за проект

API приёма платежей онлайн-школы. Три ручки (`/tariffs`, `/payments`,
`/webhooks/bank`) и уведомление банка. Главная ценность — корректность
денег и повторов, а не объём кода.

## Железные правила

1. **Деньги — только целые копейки.** Ни `float`, ни `Decimal` для хранения.
   Тип `Money` в `kvitto/domain/money.py` отвергает всё, кроме `int`.
   Делить и считать проценты — целочисленно, остаток от деления раздаём
   явно.

2. **Слои не пересекаются.**

   ```
   api ──────────► application ──► domain
   infrastructure ────────────────► domain
   ```

   - `domain` — ноль внешних импортов (нельзя даже `dataclasses`, если это
     не стандартная библиотека; точно нельзя `fastapi`/`sqlalchemy`/`pydantic`);
   - `application` знает про `domain` и порты, но не про SQLAlchemy;
   - конкретные реализации собираются только в `kvitto/api/container.py`.

   Это проверяется тестом `tests/test_architecture.py`. Если он красный —
   граница нарушена, а не тест сломан.

3. **Бизнес-правила живут в домене.** Не дублируй их в Pydantic-схемах и
   не в роутерах. Валидация формы запроса — в `api/schemas.py`. Коды
   ответов выбирает `api/errors.py`; домен про 404/409/422 не знает.

4. **Запрещённый переход статуса не меняет статус.** Единственная точка
   мутации — `Payment.change_status()`, и она бросает исключение *до*
   изменения поля. Не пиши код, который меняет `payment.status` напрямую.

5. **Идемпотентность держится уникальным индексом** по `idempotency_key`,
   а не только проверкой «есть ли такой платёж». Не убирай индекс и не
   переноси проверку в роутер.

## Стиль

- Python 3.11+, `ruff check` + `ruff format`, line length 100.
- Комментарии, докстринги и сообщения об ошибках — по-русски,
  идентификаторы — по-английски.
- Типы везде. `ruff format` не заменяет аннотации.
- Value-объекты — `frozen=True, slots=True` датаклассы.
- Комментарий объясняет **почему**, а не пересказывает код.

## Тесты

- Доменные правила тестируются без БД — они чистые функции.
- Тест API проверяет **результат**, а не только код ответа: после
  запрещённого перехода перечитывай платёж из БД.
- Перед сдачей: `ruff check . && ruff format --check . && pytest`.

## Чего не делать

Не добавляй ORM-объекты в роутеры, `HTTPException` в домен, `Decimal` в
деньги и «абстракции ради абстракций». Если кажется, что нужен новый слой
или событийная шина, сначала проверь, решает ли это задачу.
